Comparison of Rendering Pipelines

Both Chuchu and termux-ghostty utilize libghostty as their native emulation engine, but they diverge fundamentally in how they bridge cell data to the Android UI layer.

Chuchu: Rebuild Every Frame

Chuchu uses a full-screen snapshot serialization method on every draw interval. This architecture incurs high CPU and allocation overhead:

Termux-Ghostty: Incremental Deltas

Termux-ghostty updates cells incrementally. The native layer only streams changed rows using pre-allocated memory structures, minimizing Garbage Collection (GC) jitter:

Integration Feasibility Analysis

Porting termux-ghostty's Canvas system into Chuchu is highly feasible. Both applications share identical underlying libraries (Android SDK, Android NDK, Kotlin/Java, Zig-compiled libghostty native libraries).

Feasibility Rating: 9/10

Both codebases run in the JVM sandbox on Android. Porting the logic is straightforward, but the UI wrapping method needs to be decided based on Chuchu's layout design.

Integration Approaches

1. Hybrid Compose/View Wrapper (Recommended)

Using Compose's AndroidView, we wrap the native TerminalView. This brings over all optimizations, gestures, selection hooks, and scroll metrics without framework friction.

Compose Wrapper Example 
@Composable
fun ChuchuTerminalView(session: TerminalSession, modifier: Modifier = Modifier) {
    AndroidView(
        factory = { context ->
            TerminalView(context).apply {
                attachSession(session)
            }
        },
        update = { view ->
            // Apply theme/font-size changes when states update
        },
        modifier = modifier
    )
}

2. Pure Compose Rendering Port

Implement the row-caching algorithms directly in Compose DrawScope.drawIntoCanvas inside the existing TerminalCanvas.kt file. While keeping the application strictly inside the Compose tree, it retains some rendering pipeline overhead and requires rebuilding interaction structures.

GPU Rendering & Acceleration on Android

Crucial Technical Note

Both architectures are already GPU-accelerated! On modern Android, the Canvas API uses the HWUI engine under the hood, translating draw commands into OpenGL ES or Vulkan calls automatically.

Neither Chuchu nor termux-ghostty runs a custom Vulkan or OpenGL fragment shader rendering engine (like desktop Ghostty does with Metal/OpenGL). The performance bottleneck is on the CPU side, not the GPU:

  • CPU Bottleneck (Chuchu): CPU spends time allocating arrays, copying buffer bytes into JVM heaps, running Jetpack Compose layouts, and calling text layout engines for unchanged rows.
  • Low CPU Overhead (Termux-Ghostty): CPU skips unchanged lines entirely. Cells are written directly from Zig to direct native buffer memory, bypassing JVM allocations. The GPU receives only the necessary display lists.

Porting Implementation Roadmap

To implement termux-ghostty's performance optimizations into Chuchu, follow these phases:

  1. Phase 1: Align Native Serialization (Zig)

    Port the FrameDelta and SnapshotMetadata serializing functions from termux_ghostty.zig into Chuchu's bridge code. Update the JNI interface to accept pre-allocated direct ByteBuffers.

  2. Phase 2: Add Glue Caching (Java/Kotlin)

    Import ScreenSnapshot.java and implement a frame cache manager in Chuchu to update snapshots incrementally using frame deltas.

  3. Phase 3: Integrate and Wrap View

    Port TerminalView.java and TerminalRenderer.java into Chuchu, wrapping the terminal screen in a Compose AndroidView.
